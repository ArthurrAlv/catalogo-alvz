# Referências para o portfólio ALVZ

Pesquisa em 1 de novembro de 2026. Fontes primárias; recomendações abaixo são síntese editorial, não uma norma universal de portfólios.

## O que as referências fazem

- **Instrument:** reúne marca, produto e marketing na mesma seleção de trabalhos. Usa nomes de projetos, frases curtas, imagens e tags para contextualizar cada entrega; encaminha para estudos de caso. Essa abordagem sustenta uma apresentação integrada de software e identidades, sem separar Arthur em duas profissões. [Seleção de trabalhos](https://www.instrument.com/work).
- **BASIC/DEPT — Moves:** apresenta resumo, disciplinas, desafio, abordagem e opção de visitar o site. O case oferece contexto antes da saída para o produto real. Não exige uma aplicação completa incorporada para demonstrar o trabalho. [Case Moves](https://www.basicagency.com/case-studies/moves-architecture-website-design-branding).
- **BASIC/DEPT:** destaca projetos de identidade e experiências digitais no mesmo universo da agência, com descrições breves e acesso aos respectivos trabalhos. [Página principal](https://www.basicagency.com/).
- **web.dev:** recomenda layouts flexíveis, zoom permitido, unidades relativas de texto, ordem visual coerente com navegação por teclado e alvos de toque generosos (48 CSS px como orientação). [Design responsivo acessível](https://web.dev/articles/accessible-responsive-design).

## Direção recomendada para Arthur

Não há um único “padrão ouro” demonstrado por estas fontes. Há padrões recorrentes úteis: trabalho visual em primeiro plano, autoria e contexto claros, navegação simples e boa experiência móvel. O desenho específico deve acompanhar os materiais disponíveis.

1. Home curta com seleção editorial de imagens reais; nome e tags discretas por projeto.
2. Case interno: resumo de uma frase, escopo efetivamente verificado no código, telas reais e legenda funcional curta. Evitar números de impacto e narrativa de briefing que não tenham evidência.
3. Capturar interfaces dos projetos em ambiente local ou demonstrativo com dados sintéticos. As capturas devem continuar sendo a interface original, não uma reprodução aproximada desenhada para o portfólio.
4. Vídeo ou sequência de telas para fluxos importantes, quando houver material verificável. Não é requisito obrigatório para todos os projetos.
5. Botão de acesso ao produto público quando disponível. Demo interativa completa é uma camada opcional; exige isolamento dos dados e manutenção. Iframe não é a estrutura base do portfólio.
6. Logos entregues pelo usuário podem ser exibidas diretamente e ampliadas. Aplicações criadas posteriormente devem ser identificadas como estudos, sem apresentá-las como entregas históricas.
7. Hover deve apenas enriquecer; toque, teclado e links explícitos precisam oferecer o mesmo conteúdo. Animação discreta, respeitando preferência de movimento reduzido.

## Limites da pesquisa

As referências validam uma direção recorrente, não garantem conversão ou superioridade universal. Não copiar sua identidade visual, conteúdo ou ativos. Não atribuir às fontes as decisões específicas de quantidade de telas, distribuição da grade ou cores da ALVZ: são escolhas do projeto.
